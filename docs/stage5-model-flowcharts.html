ステージ 5 モデルフローチャート（敵防御・敵カウンター・敵回復）

ワールド 5（5-1〜5-4）の設計案。敵が 防御・カウンター・回復 の 3 種のカードを 使ってくるようになり、プレイヤーは「敵の作戦が書かれたフローチャート」を読んで対抗する。 図は実アプリのノード CSS（SlotNode / ConditionNode / ForNode / Card）を写して描画している。

※ 4 ステージの数値は、提案ルールを足した simulateBattle で全配置を総当たりして 「意図した置き方だけが勝つ」ことを確認済み（§4 の表）。ただし体感難易度はプレイテストで調整する前提。
※ 新カード 3 種の絵柄は未制作のため、既存カードに紫の「てき」バッジを重ねた仮表示。
※ 図のレイアウトは手描きのモデル。実機では stagesLoader の自動レイアウトになるので、座標は一致しない。

0. 前提と未決事項

項目内容
ワールド 5 の位置づけ4-4 のドラゴン撃破でエンディングが流れるので、ワールド 5 は クリア後の裏ワールド として扱う想定。マップ画像 map_5.png と maps.json のランドマーク定義は未作成。
既存の 5-1stages.json には既にコブラの 5-1（新カード未使用の総復習ステージ、demoStageIds から呼べる）が入っている。本案を採用する場合は、あれを 5-0 的な復習枠に退避するか、上書きするか を決める必要がある。
敵スプライト新規作画なしで進められるよう、既存の 16 体から流用する前提で仮に割り当てた（ナイト・ウルフ・ヒトデ・青龍）。差し替え自由。
プレイヤー HPplayer.json の 100 固定。敵の攻撃力はこれに合わせて「無対策だと死ぬ」水準にしている。

1. 新カードとルール

敵の行動は今まで通り lockedCard としてフローチャートに埋め込む。 プレイヤー側の 防御／カウンター／回復 と 完全対称 のルールにすることで、 プレイヤーは自分のカードで学んだ知識をそのまま敵の読みに使える。

ルール一覧

#ルール理由・補足
R1敵のシールド／構えは 直後の 1 マスにだけ 効くプレイヤーの guard / reflect と同じ寿命（clearTransientBuffs の対称拡張）。条件マス・合流点・for の端をはさむと消えるので、敵防御／敵カウンターは必ずスロットの直前に置く。
R2攻撃の判定順は 構え → シールド → 本体下の図 1。構え中なら全ダメージが自分へ。シールドがあれば吸収して残りだけ通る。
R3はねかえったダメージは 防げない自分の防御／カウンターも「直後 1 マス」しか持たないので、敵カウンターの直後のマスで同時に有効になることは構造上ない。ルールを足さずに済む。
R4敵のカードは 倍率マスの影響を受けない既存の monster と同じ（applyNodeEffect で mult を掛けない）。「敵防御 30 を ×3 マスに置いて 90」のような設計はしない。
R5敵回復は maxEnemyHp で頭打ちプレイヤーの heal と同じクランプ。「満タンのときに回復させる＝回復をムダにする」が戦術になる（§2 G4）。
R6構えとシールドは排他片方を出すともう片方は消える。プレイヤー側の applyGuard / applyReflect と同じ。

2. ギミック集

新カード 3 種と既存のマス（倍率・種類指定・パワーアップ・条件・くりかえし）を組み合わせて作れる 「面白い置き方の問題」を列挙する。G1〜G3・G5・G9 を 4 ステージに採用し、残りは今後のステージの種として残す。

#ギミックプレイヤーが学ぶこと採用
G1盾の直後は殴らない敵防御の次のマスに攻撃を置くと吸収される。そのマスは「空けるか、防御／回復を置く」場所。5-1
G2盾割りシールドより大きい攻撃は残りが通る。倍率マスで攻撃を育てて盾を貫く。5-4 盾フェーズ
G3構えの直後は殴らない＋攻撃専用マスの罠敵カウンターの次のマスに攻撃を置くと自分がくらう。直後に「攻撃しか置けないマス」があっても、置かない自由がある。5-2
G4満タン回復はムダ敵回復の 前 に殴ると回復で戻される。回復の 後 にまとめて殴れば回復は空振り。5-3（副次的に体験）
G5毎周回復に、育つ攻撃で追いつくパワーアップマス（0 倍 → 1 倍 → 2 倍…）の攻撃は、一定の回復をいつか必ず追い越す。長期戦なので自分の回復も要る。5-3
G6しきい値回復をまたぐ「HP が 40 以下なら 40 回復」する敵には、40 以下に とどまらない 削り方（1 周の火力 ≥ 41）が要る。種
G7周回パターンを見切るfor ループの奇数周は構え、偶数周は攻撃。同じマスが周ごとに違う意味を持つ。種
G8手を読む敵slot('slot-1') === 'attack' で敵が作戦を変える。配置そのものが敵の行動を変えるメタ読み。種
G9フェーズ制ボスHP のしきい値で作戦が切り替わる状態機械。フェーズごとに正解が違う。5-4

G2：盾割り

攻撃 15 を ×3 マスに置くと 45。敵防御 30 を引いて 15 だけ通る。攻撃 10 なら 30 − 30 = 0 で完封される。「倍率マスは盾を割るために使う」という新しい用途が生まれる。

G4：満タン回復はムダ

敵 HP 50（上限 50）。マス 1 に攻撃を置くと、直後の敵回復 30 で戻される。マス 1 は空けて、回復のあとのマス 2（×2）・マス 3 にまとめて 攻撃 20 と 10 を置けば 40 + 10 = 50 で倒せる。回復をムダ撃ちさせる気持ちよさ。

G6：しきい値回復をまたぐ

敵 HP 90（上限 90）。周の先頭で「HP が 40 以下なら 40 回復」。手札 攻撃 20 / 15 / 10 / 5、マス 1 とマス 2（×2）。
1 周の火力が 40 以下だと、HP 1〜40 の窓に落ちた瞬間に回復されて永遠に抜け出せない（runaway で負け）。 攻撃 5 + 攻撃 20 × 2 = 45 なら 90 → 45 → 0 の 2 周で、窓を一度も踏まずに倒せる。 「一番弱いカードと一番強いカードの組み合わせが最速」という意外性がある。

G7：周回パターンを見切る

くりかえし 4 回。のこり回数が 4 か 2（1・3 周目）は構え、それ以外（2・4 周目）は攻撃。マス 1 は構えの周にしか実行されないので攻撃厳禁、マス 2 は 2 回実行されるので攻撃 20 で 40 ダメージ。4-2 の forCounter 条件の応用。

G8：手を読む敵

「マス 1 が攻撃カードなら敵はカウンターの道へ、そうでなければ盾の道へ」。3-2 の slot() 条件の発展形。マス 1 に回復を置いて わざと 盾の道へ誘導し、マス 3 で盾を割る……のように、配置が敵の行動を決める。

5-4 ボス「三態の青龍（さんたいのせいりゅう）」 — 防御・回復・カウンターの全部盛り（G9・G2）

敵 青龍（仮） 敵 HP 90 手札 攻撃 15 ／ 攻撃 10 ×2 ／ 防御 40 ／ 回復 20 勝ち筋 4 / 840 通り（うち 262 通りが無限ループ）

敵 HP のしきい値で作戦が切り替わる。ループの先頭に条件を 2 段重ねるだけで「フェーズ制ボス」がフローチャートとして表現できる （loop.body の中に condition を入れ子にする既存構文のみで書ける。§4 参照）。

フェーズ敵の作戦正解の考え方
盾（HP > 60） 敵防御 30 で受け止めてから攻撃 20 盾割り（G2）。マス 1（×3）に攻撃 15 → 45 − 30 = 毎周 15 通る。攻撃 10 だと 30 − 30 = 0 で永遠に削れず runaway。
癒（60 ≧ HP > 30） 毎周 5 回復して粘る 回復量を上回る攻撃でじわじわ削る。マス 2 か 3 に攻撃 10（毎周 −5 ずつ前進、6 周）。余ったマスに回復 20 を置くと HP が満タンに戻る。
牙（HP ≦ 30） カウンターの構え → 大技 40 マス 4 は攻撃厳禁。防御 40 を置けば「カウンター回避」と「大技 40 の完封」の一石二鳥。とどめはマス 5 の攻撃 10（3 周）。

3 つのフェーズで 5-1〜5-3 の教訓をすべて回収する集大成。1 枚のカードがフェーズをまたいで何度も実行されるので、 「この 5 枚をどこに置くか」だけで戦略パズルとして成立する。840 通り中 262 通りが無限ループになるのは、 「盾を割れない」「癒フェーズで火力が回復に負ける」「牙フェーズに攻撃がない」の 3 つの停滞パターンがあるため。

ハマりポイント：攻撃 10 ×2 をマス 2・3 に置くと癒フェーズは速いが、牙フェーズに攻撃が残らず無限ループ。マス 4 に攻撃 → カウンターで被弾し火力も出ない。マス 4 を空にすると大技 40 ×3 = 120 で死亡。

5. 実装メモ

対称設計なので、既存のプレイヤー側ロジックの鏡写しで済む。ロジックの中核は下の差分だけ。

// engine/simulateBattle.js  applyNodeEffect の attack 分岐（提案）
if ((card.id === 'attack' || card.id === 'finisher') && card.power > 0) {
  const dmg = card.power * mult;
  if (enemyReflectActive) {                       // R2: 構え → 全部自分へ（R3: 防げない）
    playerHp = Math.max(0, playerHp - dmg);
  } else if (enemyGuardShield > 0) {              // R2: シールド → 吸収して残りだけ
    const absorbed = Math.min(enemyGuardShield, dmg);
    enemyGuardShield -= absorbed;
    enemyHp = Math.max(0, enemyHp - (dmg - absorbed));
  } else {
    enemyHp = Math.max(0, enemyHp - dmg);
  }
} else if (card.id === 'monster_guard' && card.power > 0) {   // R4: mult を掛けない
  enemyGuardShield = card.power; enemyReflectActive = false;    // R6: 排他
} else if (card.id === 'monster_reflect') {
  enemyReflectActive = true; enemyGuardShield = 0;
} else if (card.id === 'monster_heal' && card.power > 0) {
  enemyHp = Math.min(maxEnemyHp, enemyHp + card.power);         // R5: 上限クランプ
}
