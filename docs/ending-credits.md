# エンディングロール設計「クレジットの上を歩く」

最終ステージ（4-4）クリア後に流すエンディングロールの設計案をまとめる。
ただ眺めるスタッフロールではなく、「流れるクレジットの上に乗り続ける」遊び
要素を持たせる。

## 狙い（要件）

ユーザーから提示された要件：

1. 最終ステージクリア後に流れる**エンディングロール**であること
2. プログラミング学習ゲームらしく、**HTML/コードが流れる**ような演出にすること
3. ただ見るだけでなく**軽い遊び要素**があること（検討の結果、シューティング
   ではなく「流れるクレジットの上に乗り続け、落ちたら負け」案を採用）

## 全体コンセプト

**クレジット自体が足場になる縦スクロール足場ゲー。**

ふつうの中央ぞろえスタッフロールは行間が詰まっていて足場遊びが成立しない。
そこで、クレジットを **HTML/コード風のレイアウト**で組む。コードには最初から

- **インデント** → 足場の横のずらし
- **空行・セクション区切り** → ジャンプで越える縦の間隔
- **行ごとの長さの違い** → 足場の幅の変化

が備わっているため、「HTML が流れる」という演出自体がそのままレベルデザイン
になる。流すデータは自作 JSON なので、行間・横位置はジャンプで届く距離に完全
にコントロールできる。

**遊びの目的はコイン集め。** 行のあいだにコイン（コード風の `{}` 型）が
配置されており、行から行へ飛び移りながら取りに行く。ただ降りて生き延びる
だけでなく、「どのルートで降りればあのコインが取れるか」を考える遊びになる。
行の横位置（`x`）とコインの座標は専用の配置エディタ（後述）で GUI 編集する。

## 流すクレジットの中身

**スタッフ名は載せない。** 代わりに「キャラとプレイヤーが主役のエンディング」
として、学習のふりかえりとプレイ記録で構成する（`progressStore` にクリア済み
ステージ・見たカードの記録が既にあり、動的生成できる）。自分の冒険の記録が
流れてくることが、クレジットを読む動機にもなる。

```
<!DOCTYPE unilab>
<html>
  <head>
    <title>ユニラボ</title>
  </head>

  <body>
    <credits>

      <section class="ならったこと">
        じゅんばんに 実行《じっこう》する    ステージ 1
        くりかえす (for)                     ステージ 2
        もし〜なら (if)                      ステージ 3
      </section>

      <section class="キャスト">
        スライム 役《やく》 ... スライム     （スプライト表示）
        ロボ 役《やく》 ......... ロボ
      </section>

      <section class="きみのぼうけんのきろく">
        クリアしたステージ   16 / 16
        つかったカード       attack, guard, heal, ...
        たおしたボス         （ドラゴンのスプライト表示）
      </section>

      <section class="つかったどうぐ">
        Made with React / Vite / JavaScript
      </section>

    </credits>
  </body>
</html>
```

セクション構成（流れる順）：

1. `<!DOCTYPE unilab>` 〜 `<head>` — 導入。タイトルロゴ的な扱い
2. **ならったこと のふりかえり** — ステージで習ったプログラミング概念を
   「ならったこと: ステージ名」の形式で章立てに流す。スタッフロールの
   「役職: 名前」の置き換えで、エンディングが学習の総まとめを兼ねる
3. **キャスト紹介** — 「スライム 役《やく》 … スライム」のようにスプライト＋
   名前で登場キャラをクレジット。敵カーテンコール演出とそのまま一体化する
   （敵 14 種＋主人公＋ロボ）
4. **きみのぼうけんのきろく** — クリアしたステージ数・つかったカード一覧
   （カード画像付き）・たおしたボス。progressStore から動的生成
5. **つかったどうぐ** — 「Made with React / Vite / JavaScript」の技術
   クレジット。「このゲームもプログラミングで作られている」というメタな
   メッセージになる
6. `</html>` で閉じて終幕

ゲーム内表示テキストなので、日本語行の漢字には既存のふりがな記法
`漢字《ふりがな》` を使い、共通トークナイザ（`tokenizeFurigana.js`）で
`<ruby>` 表示する。

## 配役（何を歩かせるか）

素材は `frontend/public/sprites/` に揃っており、新規アセットは不要。

| 役割 | スプライト | 動き |
|---|---|---|
| 操作キャラ | `sprites/hero/`（右歩き 6 コマ・左歩き 7 コマ・idle 4 コマ） | プレイヤーが操作。ジャンプ専用コマは無いので歩きの 1 コマを固定表示で代用 |
| お供 | `sprites/robo/robo.png` | 当たり判定なしで主人公の後ろをふわふわ浮遊追従（マップの `RoboSprite` と同じ演出） |
| キャスト勢ぞろい | `sprites/enemies/`（14 種） | クレジットの行の上にちょこんと乗って見送る。敵意のないカーテンコール演出 |

マップで操作しているのと同じ主人公が「きみのぼうけんのきろく」の上を歩く、
という筋を通す。

## UI レイアウト

全画面 1 枚（背景 `#0b0b10` のダーク）で、コードエディタ風の見た目にする。

```
┌──────────────────────────────────────────────┐
│ のってた率《りつ》 87%                        │ ← HUD（左上、小さく）
│                                              │
│      <section class="ならったこと">          │
│                                              │
│        くりかえす (for)  ステージ 2           │
│               🤖 ← ロボ（ふわふわ追従）       │
│              🧍 ← 主人公（操作キャラ）        │
│      ──────────────                          │ ← いま乗っている行
│                                              │
│        もし〜なら (if)  ステージ 3   🐌 ←敵  │
│      ──────────────────                      │
│                                              │
│      </section>                              │
│  ↑ 全体がゆっくり上へ流れる                   │
│                              とばす(Esc長押し)│ ← 右下、小さく
└──────────────────────────────────────────────┘
```

- クレジット行は**左寄せ＋インデントあり**のコード風。
- 行は「**上からだけ乗れるすり抜け床**」（下から突き抜けてジャンプできる）。
- **行の種類＝色＝固さ**を対応させる：

  | 行の種類 | 色 | 当たり判定 |
  |---|---|---|
  | タグ行（`<section>` 等） | 金 `#f0c040` | かたい足場 |
  | 日本語の中身の行 | `#f5f0e0` | ふつうの足場 |
  | コメント行 `<!-- -->` | グレー | **すり抜け（乗れない）** |

  色の違いで足場の性質が一目で分かる、プログラミング教材らしい小ネタにする。
- フォントは他画面と同じ `DotGothic16`。ルビの CSS は
  `StoryScreen.module.css` の作法（`rt { font-size: 0.45em }` ＋
  `line-height` でルビ分の行間確保）に合わせる。

## 進行フェーズ

1. **イントロ（約 2.6 秒）**: 操作説明（← → で うごく / スペースで ジャンプ）を
   表示し、スクロールはまだ始めない。主人公は最初の行（`<!DOCTYPE unilab>`）の
   上に立った状態でスタートし猶予を持たせる。
2. **ロール本編（2〜3 分想定）**: 上記セクション構成の順で流れる。スクロール
   速度は一定（プレイヤー操作でスクロール速度は変わらない）。
3. **ラスト**: `</html>` が流れきったら中央に大きく「Thank You For Playing!」。
   主人公が生き残っていればその場で idle アニメ（バンザイ相当）。
4. **リザルトパネル**: 「あつめた コイン 18 / 22」「のれてた わりあい 87%」の
   軽い成績と「タイトルへ」「マップへ もどる」の 2 ボタン。
   **落下していても必ずここに到達する**。

## 操作と落下時の挙動

- **操作**: ←→ 移動、スペースまたは ↑ でジャンプ。キーボードのみ（他画面と同様）。
- **落下しても「負けて終了」にしない**: 画面下に落ちたら
  **見るだけモード**へ切り替わり、クレジットはそのまま普通のエンディングロール
  として最後まで流れる。ゲームが苦手でもエンディングは全部見られることを最優先
  にする。成績はそれまでに集めたコイン数と「のれてた わりあい」で残る。
- **スキップ**: 右下に小さく「とばす（Esc 長押し）」。2 回目以降の視聴用。

## 入口と出口

| 経路 | 内容 |
|---|---|
| 本編からの入口 | 4-4 クリア → `FinaleOverlay` →（既存の）エンディング紙芝居（`ending_slides.json`）→ 紙芝居を見終えた `handleEndingFinish` がマップの代わりにロール（`screen === 'credits'`）へ遷移する |
| デバッグ入口 | 既存の隠しコマンド `wqend`。紙芝居から通しで再生され、そのままロールへ続く |
| エディタ入口 | 隠しコマンド `wqedit`（配置エディタの開閉。もう一度打つか「もどる」で復帰） |
| 出口 | ロールのリザルトパネルから「タイトルへ」「マップへ もどる」 |

補足: 4-4 には `exitStage` カットシーンが定義されていないため、クリア退出時の
演出と競合しない。

## 配置エディタ（開発用ツール）

隠しコマンド `wqedit` で開く GUI エディタ
（`features/ending/editor/CreditsEditorScreen.jsx`）。クレジット全体を
1 枚の縦長キャンバスに広げ、96px グリッドの上で編集する。

- **うごかす モード**: 行をドラッグして横位置（`x`）を変える。行を
  クリックすると下部に編集パネルが開き、表示テキスト・行の種類
  （タグ / テキスト / コメント / くうはく）の変更、行の追加・削除ができる。
  コインは縦横自由にドラッグでき、ダブルクリックで削除する
- **コインをおく モード**: クリックした場所にコインを追加する
- **コインをけす モード**: クリックしたコインを削除する（赤枠表示）
- **テストプレイ**: 編集中の下書きをそのまま `CreditsScreen` で遊べる
  （JSON を書き出す前に挙動を確認できる）。「← エディタへ」で編集に戻り、
  編集内容は保持される
- **行の増減とコインの整合**: 行を追加・削除すると、それより下のコインの
  縦位置も 1 行ぶん（96px）自動でずれる。置いたコインと行の関係が崩れない
- **書き出し**: ブラウザからファイルへ直接保存できないため、
  「JSON をダウンロード」または「JSON をコピー」で書き出し、
  `frontend/src/data/ending_credits.json` を丸ごと置き換えて反映する。
  最終確認は `wqend`（紙芝居 → ロールの通し再生）

エディタ上ではプレースホルダ（下記）を見本値で表示し、行の幅（＝足場の幅）
が本番に近い見た目になるようにしている。

## 技術方針（実装済み）

- **画面追加**: `frontend/src/features/ending/CreditsScreen.jsx` ＋
  `CreditsScreen.module.css` を新設（`screen === 'ending'` は既存の
  エンディング紙芝居が使っているため、ロールは `'credits'`）。`App.jsx` の
  ルート `screen` state に 1 本足す（ルーターなしの既存方式のまま）。
- **ゲームループ**: スクロール・重力・ジャンプ・当たり判定・スプライトの
  コマ送りを `requestAnimationFrame` の 1 ループで回す。毎フレームの位置
  更新は React 再レンダーではなく ref 経由の style 直接更新
  （`map/RoboSprite.jsx` と同じ方針）。
- **当たり判定**: 行＝矩形（乗る判定は「下向き速度のときだけ、行の上辺を
  またいだか」を見るすり抜け床方式）。行の幅はマウント直後に `offsetWidth`
  で実測する。画面上端にはマージンがあり、そこより上へ流れた行は足場から
  外れる（乗ったまま画面外へ消える詰みの防止）。
- **データ**: `frontend/src/data/ending_credits.json` が
  `lines: [{kind, x, text, sprite?}]`（横位置 px 付きの全行）と
  `coins: [{x, y}]`（ワールド座標のコイン）を持つフラットな形式。
  キャスト行も静的に展開済みで、プレイヤーごとに変わる値は
  `{playerName}` / `{clearedCount}` / `{stageTotal}` / `{cardCount}` の
  プレースホルダとしてテキストに埋め込み、`buildCreditLines.js` が実行時に
  置換する。**行数と縦位置はどのプレイヤーでも変わらない**（行数が変わると
  エディタで置いたコインの位置とズレるため、「であったカード」の 1 枚 1 行
  列挙はやめて種類数の 1 行に固定した）。
- **キー入力**: window の keydown / keyup で ←→（A/D）・スペース（↑/W）・
  Esc を拾い、該当キーだけ `preventDefault`。隠しコマンド（`wqreset` 等）は
  App 側が先に capture 登録しているためロール中も効く。
