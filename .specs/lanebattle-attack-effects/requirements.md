# 要件定義: 陣取り合戦 演出強化（攻撃エフェクト・本陣キャラ）

## はじめに

おまけミニゲーム「陣取り合戦（lane battle）」の**見た目の演出を強化**する。2つの柱から成る：

1. **攻撃エフェクト**：現状はユニットの移動・HPバー・撃破演出はあるが、戦闘中に「どのキャラがどのキャラを攻撃しているか」が視覚的に分からず盤面が淡白。攻撃の瞬間に「攻撃元 → 攻撃先」へ向かう弾／斬撃のモーションを出し、戦況（誰が誰と戦っているか）をひと目で伝える。
2. **本陣キャラ**：現状の本陣は HP バー付きの柱（`.lbf-base`）だけ。以前のように**味方本陣に主人公、敵本陣に真のドラゴン（ラスボス）**を立たせ、「主人公 vs ラスボス」の構図を盤面に出して世界観を伝える。

理工展の来場者（小〜大学生）が観戦していて盛り上がる見た目を狙う。

**本機能の方針（ユーザー確定事項）**
- 見せ方は **攻撃モーションのみ**（近接＝斬撃／着弾、遠隔＝飛翔体が元→先へ飛ぶ）。
- **ダメージ数字は出さない**（多数ユニットだと画面が騒がしくなるため。将来の任意拡張とする）。
- トーンは **ピクセルアート調で程よく**（本編のドット絵意匠に合わせ、過剰にしない）。
- 既存の「多数ユニットを React 再描画せず命令的DOMで描く」設計思想を壊さない。

## 要件

### 要件1: 攻撃モーションの表示
**ユーザーストーリー：** 観戦者として、ユニットが攻撃した瞬間に攻撃モーションを見たい。なぜなら、どのキャラが今戦っているかが分かると観戦が面白くなるから。

#### 受け入れ基準
1. WHEN ユニットが攻撃を実行する（ダメージが適用される）THEN the system SHALL 攻撃元の位置から攻撃先の位置へ向かう攻撃エフェクトを1回表示する
2. WHEN 攻撃が遠隔（`ranged`）THEN the system SHALL 攻撃元から攻撃先へ**飛翔体**が飛ぶモーションを表示する
3. WHEN 攻撃が近接 THEN the system SHALL 攻撃先（被弾側）の位置に**斬撃／着弾**のモーションを表示する
4. WHEN エフェクトのアニメーションが終了する THEN the system SHALL そのエフェクト要素を自動的に取り除く（DOMに残さない）
5. IF 同一フレームで複数の攻撃が発生する THEN the system SHALL それぞれに対応するエフェクトを個別に表示する

### 要件2: 攻撃元→攻撃先の「向き」が分かる
**ユーザーストーリー：** 観戦者として、攻撃が「どちらからどちらへ」飛んでいるか分かりたい。なぜなら、攻防の向き（自軍→敵軍 / 敵軍→自軍）が分かると戦況が読めるから。

#### 受け入れ基準
1. WHEN 攻撃エフェクトを表示する THEN the system SHALL 攻撃元と攻撃先の仮想座標（`x`・`lane`）に基づいて、向き・位置が正しくなるよう配置する
2. WHEN 攻撃元の `side`（`you`/`cpu`）が異なる THEN the system SHALL 自軍の攻撃と敵軍の攻撃を見分けられるよう（色・向き等で）区別する
3. IF 飛翔体が元→先へ飛ぶ THEN the system SHALL 飛翔の向き（左右）が攻撃元→攻撃先の位置関係と一致する

### 要件3: 対象となる攻撃の種類
**ユーザーストーリー：** 観戦者として、盤面で起きる主要な攻撃すべてにエフェクトを見たい。なぜなら、一部だけ光ると不自然だから。

#### 受け入れ基準
1. WHEN ユニットが敵ユニットを攻撃する THEN the system SHALL エフェクトを表示する
2. WHEN ユニットが敵本陣（タワー）を直接攻撃する THEN the system SHALL 攻撃元から本陣へ向かうエフェクトを表示する
3. WHEN 本陣（防衛）が侵入ユニットを攻撃する THEN the system SHALL 本陣から対象ユニットへ向かうエフェクトを表示する
4. WHERE 範囲攻撃（`splash`/`pierce`）the system SHALL 範囲攻撃であることが伝わる表現（着弾を広めにする等）を任意で付けてよい（必須ではない）

### 要件4: 既存設計・パフォーマンスとの整合
**ユーザーストーリー：** 開発者として、多数ユニットが動く中でもエフェクトで重くならず、既存のシム純粋性を保ちたい。なぜなら、ゲームの滑らかさと保守性を壊したくないから。

#### 受け入れ基準
1. WHEN シミュレーション（`engine/stepSim.js`）が攻撃を解決する THEN the system SHALL 攻撃イベント（攻撃元・先・種別）を状態上のキューに積むだけにし、**DOMには一切触れない**（純関数性を維持）
2. WHEN 1フレーム分の更新が終わる THEN the system SHALL 描画側（`createRenderer`）がそのキューを読み、既存ユニット層と同じ座標系（`x/virtualWidth*100 %`）でエフェクトDOMを命令的に生成し、消費後キューをクリアする
3. IF エフェクトが多数同時発生する THEN the system SHALL React の再描画を増やさず（命令的DOM・自走remove）、既存のユニット描画と同一系統で処理する
4. WHEN 試合が終了・リセットされる THEN the system SHALL 残っているエフェクト要素を適切に片付ける（盤面に残さない）

### 要件5: トーン・非目標
#### 受け入れ基準
1. WHEN エフェクトを描く THEN the system SHALL 本編のドット絵意匠（`image-rendering: pixelated` 等）に合うピクセルアート調にし、過剰な装飾を避ける
2. IF ダメージ数値表示が要望される THEN the system SHALL それを**本機能のスコープ外**とする（今回は出さない。将来の任意拡張）
3. WHEN 攻撃間隔が短いユニットが連射する THEN the system SHALL エフェクトが画面を覆い尽くさない程度の軽さ（短時間で消える・控えめなサイズ）にする

### 要件6: 攻撃種別による出し分け
**ユーザーストーリー：** 観戦者として、近接と遠隔の攻撃が見た目で違うと分かりやすい。なぜなら、ユニットの個性（弓兵っぽい・殴り系っぽい）が伝わると面白いから。

#### 受け入れ基準
1. WHEN ユニット定義（`deriveUnitDef` の `def`）が `ranged`（射程が遠隔しきい値以上）THEN the system SHALL 飛翔体系のエフェクトを使う
2. WHEN `ranged` でない（近接）THEN the system SHALL 斬撃／接触系のエフェクトを使う
3. WHERE 攻撃種別ごとに色・形を変える the system SHALL データ（ユニット種別や `def` のフラグ）から見た目を決められる拡張しやすい作りにする（キャラごとの細かな専用エフェクトは必須ではない）

### 要件7: 本陣にキャラクターを立たせる
**ユーザーストーリー：** 観戦者として、味方本陣に主人公、敵本陣に真のドラゴンが立っているのを見たい。なぜなら、「主人公 vs ラスボス」の構図が盤面に出ると世界観が伝わって盛り上がるから。

#### 受け入れ基準
1. WHEN 盤面を描画する THEN the system SHALL 味方本陣（`you`）の位置に**主人公（`hero`）**のスプライトを立たせる
2. WHEN 盤面を描画する THEN the system SHALL 敵本陣（`cpu`）の位置に**真のドラゴン（`dragon_final`＝しんのドラゴン）**のスプライトを立たせる
3. WHEN 本陣キャラを表示する THEN the system SHALL idle アニメーション（コマ送り）で待機表示する
4. WHEN 本陣キャラを配置する THEN the system SHALL 既存の本陣HPバー（`.lbf-base`）と重なって邪魔しないよう配置する（HPバーは引き続き視認できる）
5. WHEN 本陣キャラの向き THEN the system SHALL 敵方向を向く（または自然な向き）よう、味方=右向き／敵=左向き等で対峙させる
6. WHERE 本陣が攻撃・被弾する the system SHALL 本陣キャラの位置を攻撃エフェクトの「攻撃元／攻撃先」の基準に使ってよい（要件3と連携）
7. IF 本陣が陥落（HP0）する THEN the system SHALL 本陣キャラの最終的な見せ方（撃破／消滅など）を任意で検討してよい（必須ではない。最低限は立たせるだけでよい）
