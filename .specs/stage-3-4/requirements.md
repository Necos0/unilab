# 要件定義: ステージ 3-4（差し替え・カウンターと分岐読み）

## はじめに

ワールド3の最終ステージ 3-4 を、原案 `3-4.jpg`（手書き・作者解説）に沿って差し替える。テーマは **「敵HP条件の分岐を読み、カウンター（reflect）で敵の大技を反射して削り切る」**。攻撃カードの素点だけでは足りず、**カウンターで敵攻撃を反射する量**が勝敗を決める。敵は現行の `lagiacrus` を踏襲する。

本ステージの核は **「カウンターを張った直後に条件分岐マスがあり、分岐先の敵攻撃を反射する」** 構成（⑦）。これを成立させるため、**条件分岐マスを merge と同様の“構造マス”として扱い、バフ（シールド/反射）を消費せず透過させる**エンジン改修を行う。

### 定数・手札・解答（確定）
- 自HP=95 / 敵HP=95
- 手札（10枚＝10スロット）：攻4・攻4・攻7・攻7・攻25 ／ 防10・防11・防11 ／ カウンター(reflect)×2
- 解答：①攻7・②攻4・③防11・④防11・⑤攻7・⑥防10・⑦reflect・⑧攻4・⑨reflect・⑩攻25
- 通る分岐：**①=×（[3]側）・②=○（[6]側）・③=○（m28側）**。②攻4・⑧攻4 は通らない経路に置く「捨てカード」。

## 要件

### 要件1: 条件分岐マスのバフ透過（構造マス化）
**ユーザーストーリー：** ステージ作者として、カウンターを張った直後に分岐を置き、分岐先の敵攻撃を反射させたい。なぜなら「読み合い（分岐）とカウンターの組み合わせ」を表現したいから。

#### 受け入れ基準
1. WHEN バフ（シールド/反射）が有効なまま条件分岐マスを通過する THEN the system SHALL バフを消費せず分岐先の最初のマスへ通す（merge と同じ透過）
2. WHEN sim（`clearTransientBuffs`）と live（`battleStore` エッジ処理）THEN the system SHALL `condition` を `merge` と同一に「構造マス＝バフ透過」として扱う
3. WHEN 条件分岐マスの直前が敵攻撃（monster）等でバフが無い既存ステージ THEN the system SHALL 挙動を変えない（バフが無ければ透過しても差が出ない）

### 要件2: ステージ対戦パラメータ
#### 受け入れ基準
1. WHEN `3-4` を開始する THEN the system SHALL 敵=lagiacrus・敵HP=95・自HP=95・手札10枚で初期化する
2. WHEN 読み込む THEN the system SHALL 10スロット（明示id p1〜p10）を用意する（倍率・種類指定マスは無し）

### 要件3: フロー構造の忠実な再現
（m=敵攻撃。[n]=プレイヤーマス。○=true 経路、×=false 経路）
#### 受け入れ基準
1. WHEN 構築する THEN the system SHALL `START→[1]→m(5)→◇「敵HP≦85」(○:[2]→m(11) / ×:[3]→m(21)→m(25)→[4])` を置く
2. WHEN 構築する THEN the system SHALL 合流後 `→m(22)→[5]→◇「敵HP>75」(○:[6]→m(9) / ×:m(12))` を置く
3. WHEN 構築する THEN the system SHALL 合流後 `→m(31)→[7]→◇「敵HP>70」(○:m(28) / ×:m(18)→[8])` を置く
4. WHEN 構築する THEN the system SHALL 合流後 `→m(12)→[9]→m(29)→[10]→goal` を置く

### 要件4: 解答の成立とパズル意図
#### 受け入れ基準
1. WHEN 解答どおり配置して実行する THEN the system SHALL 敵HPを0にし自HP≥1でクリアする（分岐 ×/○/○ を通り、⑦で m(28)・⑨で m(29) を反射、最終 自HP=1）
2. IF ⑦/⑨ に reflect 以外 THEN the system SHALL 敵の大技を反射できず（⑦は m(28) を被弾して）敗北する
3. IF ⑩ に攻25 以外 THEN the system SHALL 火力が足りずクリアできない
4. IF ③④⑥ に十分な防御（合計31以上）を置かない THEN the system SHALL 道中の被弾に耐えられず敗北する
5. IF ① に攻25 を置く（敵HPを85以下にして分岐①を○にする）THEN the system SHALL 反射できる最大が不足しクリアできない

### 要件5: 非回帰・ビルド
#### 受け入れ基準
1. WHEN 条件透過を追加する THEN the system SHALL 既存の分岐ステージ（3-1〜3-3・5-2・5-3・5-4 等）の解答成立を変えない（検証で 5-2/5-3/5-4=win、3-1 は guard/reflect カード無し、3-2/5-3 は条件前が敵攻撃、3-3 は reflect を最終 monster の直前に置くため条件にバフが乗らない）
2. WHEN `3-4` を差し替える THEN the system SHALL 他ステージの定義・展開・結末を変更しない
3. WHEN build/lint を実行する THEN the system SHALL エラーなく通過する
