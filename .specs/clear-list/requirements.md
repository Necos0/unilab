# 要件定義: クリア者一覧（タイトルから閲覧）

## はじめに

本番（理工展）後に URL を開く人向けに、タイトル画面から**クリア者の一覧**を見られるようにする。当日は会場モニター用の `/screen`（`ClearScreen`）で「その日のクリア者」を自動スクロール＋演出で流していたが、今回欲しいのは **過去の全クリア者を、自分でスクロールして閲覧できる一覧**。あわせて「今日だけ」に絞るトグルも付ける。

会場用の `/screen`（別 URL・自動スクロール・演出）は**変更しない**。本機能はタイトルから開く別画面として追加する。

**用語・既存資産**
- クリア記録は Supabase の `users` テーブル（`id, nickname, started_at, cleared_at`）。クリア＝`cleared_at` が入っている行。
- クリアタイム＝`cleared_at - started_at`（`formatClearTime` で整形）。順位＝タイムの速い順（`ClearScreen` と同じ）。順位マークは `RankBadge`（金銀銅＋王冠）。
- 取得は `clearRecordApi.js`（現状 `fetchTodayClears`＝今日分のみ `gte cleared_at 今日0時`）。全件取得は未実装。
- 会場表示は `/screen`（`main.jsx` が `window.location.pathname === '/screen'` で `ClearScreen` を出す）。本編タイトルは `App` の `screen` 状態遷移。

## 要件

### 要件1: タイトルの「クリア者一覧」ボタン
**ユーザーストーリー：** 後からURLを開いた人として、タイトルからクリア者一覧を開きたい。当日の盛り上がりを後からでも見られるようにするため。

#### 受け入れ基準
1. WHEN タイトル画面を表示する THEN the system SHALL 「クリア者一覧」ボタンを、「つづきの ぼうけんへ」ボタンの**下に同じくらいの大きさ**で表示する（「つづきの ぼうけんへ」が非表示のプレイヤーでも、クリア者一覧ボタンは常に表示する）。
2. WHEN 「クリア者一覧」ボタンを押す THEN the system SHALL クリア者一覧画面へ遷移する。
3. WHEN 一覧画面から戻る操作をする THEN the system SHALL タイトル画面へ戻る。

### 要件2: 全クリア者の一覧（手動スクロール）
**ユーザーストーリー：** 閲覧者として、過去の全クリア者を自分のペースでスクロールして見たい。自動で流れると見たい人を追えないから。

#### 受け入れ基準
1. WHEN 一覧画面を開く THEN the system SHALL 過去を含む**全クリア者**（`cleared_at` のある行）を取得して並べる。
2. WHEN 一覧を表示する THEN the system SHALL **自動スクロールせず**、ユーザーが手で縦スクロールできる形式にする。
3. WHEN 一覧を並べる THEN the system SHALL クリアタイムの速い順（同タイムはクリア時刻の早い順）に順位付けする。
4. WHEN 一覧画面の見た目を作る THEN the system SHALL 会場用 `ClearScreen` と**同じ見た目**（背景・行・順位装飾・配色）にする。歩く勇者・ドラゴン等の**キャラ演出は後日（余裕があれば）コピー**し、まずは一覧の見た目を合わせる。

### 要件3: 各行の表示
#### 受け入れ基準
1. WHEN 1人分の行を表示する THEN the system SHALL 順位（`RankBadge`）・ニックネーム・クリアタイム（`formatClearTime`）を表示する。
2. WHERE 上位（1〜3位）the system SHALL 既存の金・銀・銅の装飾を流用してよい。
3. テキストはふりがな・やさしい言葉の方針（CLAUDE.md）に従う。

### 要件4: 「今日だけ」フィルタ
**ユーザーストーリー：** 閲覧者として、全体と今日分を切り替えて見たい。当日来た人は「今日の分」だけ見たいこともあるから。

#### 受け入れ基準
1. WHEN 一覧画面に絞り込みトグルを表示する THEN the system SHALL 「ぜんぶ」/「今日だけ」を切り替えられるようにする。
2. WHEN 「今日だけ」を選ぶ THEN the system SHALL `cleared_at` が今日（`getTodayStart` 以降）の行だけを表示する。
3. WHEN 既定表示 THEN the system SHALL 「ぜんぶ」（全クリア者）にする。

### 要件5: データ取得と異常系
#### 受け入れ基準
1. WHEN 一覧を開く THEN the system SHALL `clearRecordApi` の全件取得（新規 `fetchAllClears`）で `id, nickname, started_at, cleared_at` を取る。
2. IF Supabase が未設定（`isClearRecordEnabled()===false`）THEN the system SHALL タイトルのボタンは**出したまま**にし、一覧画面の中で「準備中」の旨を表示する（クラッシュしない）。
3. IF 取得が0件 THEN the system SHALL 「まだ クリアした人が いないよ」等の空表示を出す。
4. IF 取得に失敗する THEN the system SHALL エラーで画面を壊さず、取得失敗の旨を表示する。
5. 本機能は閲覧専用（新規の書き込み・Realtime購読は必須ではない。開いた時点の一覧でよい）。

### 要件6: 会場用 /screen は不変
#### 受け入れ基準
1. WHILE 本機能を追加する間 the system SHALL `/screen`（`ClearScreen`：自動スクロール・演出・今日分）の挙動を変えない。
2. 共通化する場合でも `/screen` の見た目・動作に影響を出さない（流用は読み取り専用の関数・部品にとどめる）。

### 要件7: 自分がクリアしたとき、自分の画面に祝福演出
**ユーザーストーリー：** プレイヤーとして、自分がクリアした瞬間に、会場モニターに出ていたお祝い演出を自分の画面でも見たい。達成感が上がるから。

#### 受け入れ基準
1. WHEN プレイヤーのクリアが記録される（計測終了＝`markCleared`／エピローグ完了のタイミング）THEN the system SHALL 会場用と同じ祝福演出（`ClearCelebration`：画面を暗くして「クリア おめでとう！」＋ニックネーム＋紙ふぶき→フェードアウト）を**本人の画面に1回**表示する。
2. WHEN 祝福演出を出す THEN the system SHALL ニックネームに本人の名前（`playerStore.playerName`）を使う。
3. WHEN 祝福演出のアニメが終わる THEN the system SHALL 演出を閉じ、以降の画面遷移（エンディング等）を妨げない。
4. WHERE Supabase 未設定・オフライン the system SHALL 記録の成否に関わらず演出は出してよい（演出は見た目だけで、記録とは独立に扱う）。

## 決定事項（判断の回答）

- **【判断1】画面の作り → 新規**：会場用とは別の新しい画面を作る。ただし**見た目は `ClearScreen` と同じ**にする（流用は読み取り専用にとどめ `/screen` は不変）。
- **【判断2】装飾 → 後日**：まず順位・名前・タイムの一覧（見た目は会場用と同じ）。歩く勇者・ドラゴン等のキャラ演出は作り終えて余裕があればコピー。
- **【判断3】並び順 → タイム速い順**（`/screen` と同じリーダーボード）で確定。
- **【判断4】取得件数 → 上限あり**：全件だが上限（例 1000件）。期間は「ぜんぶ／今日だけ」のみ。
- **【判断5】ボタン位置 → 「つづきの ぼうけんへ」の下**に同じくらいの大きさ。常に表示。文言「クリア者一覧」。
- **【判断6】Supabase 無効時 → ボタンは出す**。一覧画面内で「準備中」表示。
- **【判断7】更新 → 開いた時点の一覧**（Realtime 購読なし・閲覧専用）。
- **【追加】要件7** を新設（クリア時に本人画面へ祝福演出）。
