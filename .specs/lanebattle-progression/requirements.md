# 要件定義: 陣取り合戦 進行連動アップデート

## はじめに

陣取り合戦（おまけミニゲーム）を 2-4 クリアで早期解放したことに伴い、本編の進行度に連動した体験へ作り替える。本編でまだ出会っていないキャラはネタバレになるため使えないようにし（「？」表示・選択不可）、ストーリーを進めるほど使えるキャラ・遊べる難易度が増える設計にする。あわせて CPU 難易度を 3 段階に分け、UI（エナジー表示）とユニット配置の操作性（ドラッグ）も改善する。

対象プレイヤーは理工展の来場者（小〜大学生）。本編の進捗（`progressStore.clearedStageIds`）を唯一の解放ソースとし、二重管理しない。

**今回のスコープ**：要件1〜8（キャラ解放・「？」・案内・CPU進行連動・難易度3段階と選択UI）。**要件9（ドラッグ配置）・要件10（エナジーUI変更）は今回スコープ外（後日対応）**。

**用語**
- 「登場キャラ」：`stages.json` の各ステージ `enemyId`。そのステージをクリアすると、その敵キャラが陣取りで解放される。
- 「キャラ→初出ステージ」対応（`stages.json` から機械導出）：slime=1-1, wolf=1-2, knight=1-3, golem=1-4, cactus=2-1, scorpion=2-2, cobra=2-3, goldenbird=2-4, starfish=3-1, squid=3-2, shark=3-3, lagiacrus=3-4, crab=4-1, lizard=4-2, phoenix=4-3。**mecha_dragon はデフォルト（常に解放）**。
- 「難易度」：対戦する CPU の強さ（☆×1 / ☆×2 / ☆×3）。プレイヤーの編成は難易度に関わらず常に「解放済みキャラから選ぶ」。

## 要件

### 要件1: キャラの進行連動アンロック
**ユーザーストーリー：** プレイヤーとして、本編で出会ったキャラだけを陣取りで使いたい。まだ会っていないキャラが見えるとネタバレになるから。

#### 受け入れ基準
1. WHEN 編成画面（`DeckBuilder`）を表示する THEN the system SHALL 各ロスターキャラの初出ステージが `clearedStageIds` に含まれるものだけを「選択可能」にする。
2. WHERE `mecha_dragon` the system SHALL 進行に関わらず常に選択可能（デフォルト解放）にする。
3. IF キャラの初出ステージが未クリア THEN the system SHALL そのキャラを「未解放」として扱う（選択不可）。
4. 解放判定は `clearedStageIds` からの派生とし、解放済み集合を二重に保存しない。

### 要件2: 未登場キャラの「？」表示・選択不可
**ユーザーストーリー：** プレイヤーとして、未解放キャラは中身を伏せて見たい。何が増えるかのワクワクは残しつつ、ネタバレは避けたいから。

#### 受け入れ基準
1. WHEN 編成画面で未解放キャラを表示する THEN the system SHALL 名前・画像・ステータスを伏せて「？」表示にする。
2. WHEN 未解放キャラの枠を操作する THEN the system SHALL 選択・編成への追加をできなくする（タップ無効）。
3. WHEN 解放済みキャラを表示する THEN the system SHALL 通常どおり名前・画像・ステータスを見せる。

### 要件3: 「進めると増える」案内
**ユーザーストーリー：** プレイヤーとして、キャラが増える条件を知りたい。なぜ「？」なのか分かると本編を進める動機になるから。

#### 受け入れ基準
1. WHEN 編成画面に未解放キャラが1つ以上ある THEN the system SHALL 「ストーリーを すすめると つかえる キャラが ふえるよ」の旨を目立つ位置に表示する。
2. 文言はふりがな・やさしい言葉の方針（CLAUDE.md）に従う。

### 要件4: CPU も進行連動（未登場キャラを使わない）
**ユーザーストーリー：** プレイヤーとして、CPU もまだ会っていないキャラを出さないでほしい。CPU が未登場キャラを出すとネタバレになるから。

#### 受け入れ基準
1. WHEN CPU がユニットを編成・出撃する THEN the system SHALL 解放済み（＝プレイヤーと同じ基準）のキャラだけを使う。
2. WHERE 難易度が固定デッキ（☆×2/☆×3）the system SHALL その固定デッキが、解放条件を満たす進行度でのみ選べることで整合を保つ（固定デッキのキャラは全て解放済み）。

### 要件5: CPU 難易度 3 段階と解放条件
**ユーザーストーリー：** プレイヤーとして、進行に応じて歯ごたえのある相手と戦いたい。本編を進めた分だけ強い敵に挑めると達成感があるから。

#### 受け入れ基準
1. WHEN 2-4 をクリア済み THEN the system SHALL 難易度 ☆×1 を解放する。
2. WHEN 3-4 をクリア済み THEN the system SHALL 難易度 ☆×2 を解放する。
3. WHEN 4-4 をクリア済み THEN the system SHALL 難易度 ☆×3 を解放する。
4. WHEN 編成画面（`DeckBuilder`）の**下部に横並びで置く難易度ボタン（☆×1 / ☆×2 / ☆×3）**を押す THEN the system SHALL その難易度の CPU との対戦画面へ遷移する（難易度ボタン＝対戦開始を兼ねる）。
5. IF 未解放の難易度 THEN the system SHALL そのボタンをロック表示にして押せなくする。

### 要件6: ☆×1 の挙動（ランダム）
**ユーザーストーリー：** 初めて遊ぶプレイヤーとして、やさしい相手で練習したい。操作に慣れる前から強い CPU だと楽しめないから。

#### 受け入れ基準
1. WHEN 難易度 ☆×1 の CPU が編成を決める THEN the system SHALL 解放済みキャラ（2-4 までのキャラ＋mecha_dragon）からランダムに 6 枚選ぶ。
2. WHEN ☆×1 の CPU がユニットを出す THEN the system SHALL 手札からランダムに 1 枚選び、配置可能なマスの中からランダムな場所に出す（戦術的判断はしない）。
3. WHILE エナジーが足りない the system SHALL 出せる札が出るまで待つ（最低限の妥当性のみ保つ）。

### 要件7: ☆×2 の挙動（固定デッキ＋既存アルゴリズム）
#### 受け入れ基準
1. WHEN 難易度 ☆×2 THEN the system SHALL CPU デッキを固定「ラギアクルス・イカ・サメ・ナイト・コブラ・ウルフ」（lagiacrus, squid, shark, knight, cobra, wolf）にする。
2. WHEN ☆×2 の CPU が出撃判断する THEN the system SHALL 既存の思考アルゴリズム（`cpuBrain.decideCpu`）を用いる。
3. 難易度パラメータは現行 `normal`（reactionMs 500 / accuracy 0.7 / energyRegenMul 1.0 / missChance 0.15）を用いる。

### 要件8: ☆×3 の挙動（固定デッキ＋既存アルゴリズム・最高難度）
#### 受け入れ基準
1. WHEN 難易度 ☆×3 THEN the system SHALL CPU デッキを固定「メカドラゴン・トカゲ・イカ・サメ・カニ・ウルフ」（mecha_dragon, lizard, squid, shark, crab, wolf）にする。
2. WHEN ☆×3 の CPU が出撃判断する THEN the system SHALL 既存の思考アルゴリズムを強化パラメータ（reactionMs 300 / accuracy 0.9 / energyRegenMul 1.3 / missChance 0.05）で用いる。

### 要件8.5: プレイヤー編成と難易度の独立
#### 受け入れ基準
1. WHEN どの難易度でも THEN the system SHALL プレイヤーの編成は常に「解放済みキャラから 6 枚選ぶ」（難易度は CPU の強さのみを変える）。

### 要件9:（今回スコープ外・後日）ドラッグによるユニット配置
**ユーザーストーリー：** プレイヤーとして、カードをドラッグしても出せると直感的で速い。本編のカード配置と操作感をそろえたいから。

#### 受け入れ基準
1. WHERE 時間に余裕がある the system SHALL 既存のクリック配置に加え、手札カードをクリック＆ドラッグして配置マスへドロップする操作でも出撃できるようにする。
2. WHEN ドラッグ配置する THEN the system SHALL クリック配置と同じ配置可否・エナジー消費・結果にする（挙動を二重化しない）。
3. この要件は他要件完了後の追加実装とする（優先度は低、【判断5】）。

### 要件10:（今回スコープ外・後日）エナジー UI の変更
**ユーザーストーリー：** プレイヤーとして、エナジー量と手札を近くで見たい。視線移動を減らして出すか待つか判断したいから。

#### 受け入れ基準
1. WHEN HUD を表示する THEN the system SHALL エナジー数値表示（「n/100」）を手札のある左側へ移す。
2. WHEN エナジーバーを表示する THEN the system SHALL 数値の右側に置き、現在より短くする。
3. 加速倍率（⏩×n）等の既存情報は維持する（配置は【判断4】）。

## 決定事項（判断の回答）

- **【判断1】難易度の選び方 → 選択制**：`DeckBuilder` 下部に ☆×1/☆×2/☆×3 の難易度ボタンを横並びに置き、押すとその難易度の対戦画面へ遷移（ボタン＝対戦開始）。未解放はロック表示。
- **【判断2】☆×3 パラメータ → 採用**：☆×2＝normal（500/0.7/1.0/0.15）、☆×3＝強化（300/0.9/1.3/0.05）。
- **【判断3】解放基準 → `clearedStageIds`（クリアで解放）**。
- **【判断4】エナジー UI（要件10） → 今回スコープ外（後日）**。
- **【判断5】ドラッグ配置（要件9） → 今回スコープ外（後日）**。
- **【判断6】「？」の見せ方 → 採用**：編成画面でカードを「？」に伏せる・並びは解放順のまま。CPU 側は UI なしで候補から除外のみ。
- **【判断7】案内文言・位置 → 採用**：「ストーリーを すすめると つかえる キャラが ふえるよ」を編成画面の目立つ位置（上部バナー想定）。
- **【判断8】保存デッキ → 自動除外**：保存デッキに未解放キャラが混ざる場合は自動的に除外する（通常プレイでは起こらない前提）。
