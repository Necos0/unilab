# 進め方（作業分割）: 陣取り合戦 3レーン版

## この文書の役割

`requirements.md`（全体の要件・ビジョン）は据え置き。実装は大きな設計書を一気に作らず、**小さな作業ユニットに分割して 1 つずつ spec 駆動**で進める。各ユニット＝「集中設計 → teaching モードで本人が実装 → 検証 → 次へ」。各ユニットの設計は `design-0X-*.md` に置く（必要になった時点で作成）。

## 横断原則（全ユニット共通）

- **シミュレーションと描画を分離**：勝敗が決まる計算（state と step）は DOM/React に依存しない純ロジックにする。描画は state を読んで反映するだけ。→ 要件 8、headless テストのしやすさ、将来の PvP／リプレイ。
- **入力駆動・決定的**：状態変化は「デプロイ入力（誰が・どのカードを・どのレーン・どの位置に出したか）」で駆動する。乱数は seed 付き RNG を state に注入し、`Math.random` 直書きをやめる。→ 要件 8。
- **数値は config に**：レーン数・配置ゾーン・射程・探知距離・制限時間・スコア係数・難易度プリセットは `lanebattle_config.json`／ユニット定義に置く。ロジックに定数を埋めない（既存方針の踏襲）。
- **既存の置き換えは最後**：新モジュールは追加的に作り、1 レーン版との差し替え（要件 7）は仕上げユニットで一括で行う。dev ブランチ上なので、途中の未完成状態は許容する。

## 作業ユニットと順序

1. **フィールド整備** … 3 レーン＋自陣の配置ゾーン＋本陣（盤面の描画と state の土台）… `design-01-field.md`
2. **キャラ移動・交戦** … 探知距離／前進・後退／レーン内交戦（既存の特殊能力を移植）
3. **配置 UI** … カード選択 → レーン×前後セルをタップして出撃（入力→デプロイコマンド）
4. **反応型 CPU** … 脅威評価・カウンター選択・前後配置・難易度ダイヤル
5. **スコア計算** … 制限時間・勝敗判定・「勝ち＝一定点＋残り時間ボーナス／未決着＝与ダメージ」・結果画面
6. **難易度選択 UI** … やさしい／ふつう／むずかしい → CPU ダイヤルへ
7. **仕上げ・置き換え** … 1 レーン版と差し替え、バランス調整、隔離の最終確認

依存関係：1 → 2 → 3、2 → 4、5 は 1・2 に、6 は 4 に依存。基本は上から順に進める。

## 各ユニットの進め方（teaching モード）

1. Claude が `design-0X-*.md`（設計＋そのユニットのタスク）を書く。
2. 内容をレビューして合意する。
3. Claude がコードを「提案」→ 本人が実装 →「完了」報告 → Claude が検証し docstring を記入。
4. 次のユニットへ。
